---
title: اسٹیجنگ، اور غلطیاں واپس لینا
summary: بالکل وہی چنیں جو ہر کمٹ میں جائے، اور جب کوئی تبدیلی بگڑ جائے تو فائل واپس لائیں۔
---

git آپ کی فائلوں کو تین جگہوں پر دیکھتا ہے:

- **فولڈر** — آپ کی فائلیں جیسی ابھی ہیں؛
- **اسٹیجنگ ایریا** — اگلے کمٹ میں کیا ہوگا (`git add` تبدیلیاں یہاں رکھتا ہے)؛
- **کمٹس** — وہ ورژن جو آپ نے محفوظ کیے۔

چونکہ آپ چنتے ہیں کہ کیا اسٹیج کرنا ہے، اس لیے ہر کمٹ میں ایک خیال ہو سکتا ہے۔ صفحہ _اور_ رنگ دونوں بدلے؟ پہلے صفحہ اسٹیج اور کمٹ کریں، پھر رنگ: واضح پیغامات والے دو چھوٹے کمٹس ایک بڑے کمٹ سے سمجھنا آسان ہوتے ہیں۔

```text
git status                   اسٹیج شدہ اور غیر اسٹیج شدہ تبدیلیاں دکھاتا ہے
git diff                     وہ تبدیلیاں جو ابھی اسٹیج نہیں ہوئیں
git diff --staged            اسٹیج شدہ تبدیلیاں
git restore index.html       فائل کی تبدیلیاں ختم کریں (اسٹیج شدہ ورژن پر واپس)
git restore --staged a.css   فائل کو اَن اسٹیج کریں (تبدیلی فولڈر میں رہتی ہے)
```

`git restore` کے ساتھ احتیاط کریں: جو تبدیلیاں آپ ختم کرتے ہیں وہ چلی جاتی ہیں۔ اسی لیے بار بار کمٹ کریں۔

### یہ سبق کیسے کام کرتا ہے

بائیں طرف آپ کے پروجیکٹ کا فولڈر ہے: کسی فائل کو منتخب کر کے اس میں تبدیلی کریں (لکھتے ہی تبدیلیاں محفوظ ہو جاتی ہیں)۔ دائیں طرف **ٹرمینل** ہے: کمانڈ لکھیں اور **Enter** دبائیں۔ یہاں استعمال ہونے والی تمام کمانڈز دیکھنے کے لیے `help` لکھیں۔ جب لگے کہ کام مکمل ہو گیا ہے تو **میرا کام چیک کریں** دبائیں۔
