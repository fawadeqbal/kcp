---
title: برانچز
summary: کسی آئیڈیا کو برانچ پر آزمائیں اور کام کرنے والا ورژن خراب نہ ہو، پھر تیار ہونے پر اسے مرج کریں۔
---

**برانچ** کمٹس کی ایک لائن ہے۔ ہر ریپوزٹری ایک برانچ سے شروع ہوتی ہے جس کا نام `main` ہے: یہ وہ ورژن ہے جو کام کرتا ہے۔ جب آپ کچھ آزمانا چاہیں — ڈارک موڈ یا نیا صفحہ — تو **نئی برانچ** بنائیں، وہاں کام کریں، اور `main` محفوظ رہتی ہے۔

```text
git branch                     برانچز کی فہرست (* بتاتا ہے آپ کس پر ہیں)
git switch -c dark-mode        dark-mode نام کی برانچ بنائیں اور اس پر جائیں
git switch main                واپس main پر جائیں
git merge dark-mode            dark-mode کے کمٹس موجودہ برانچ میں لائیں
git branch -d dark-mode        مرج ہونے کے بعد برانچ حذف کریں
```

برانچ بدلنے پر git آپ کے فولڈر کی فائلیں اس برانچ کے مطابق کر دیتا ہے۔ کچھ ضائع نہیں ہوتا: کمٹس اپنی برانچ پر موجود رہتے ہیں۔

**مرج** دوسری برانچ کا کام لے آتا ہے۔ اگر برانچ بننے کے بعد `main` نہیں بدلی تو git بس `main` کو آگے بڑھا دیتا ہے ("fast-forward")۔ اگر دونوں برانچز میں نئے کمٹس ہوں تو git ایک **مرج کمٹ** بناتا ہے جو دونوں کو جوڑتا ہے۔

ٹیم میں ہر کوئی اپنی برانچ پر کام کرتا ہے اور کام تیار ہونے پر `main` میں مرج کرتا ہے — عام طور پر **پُل ریکویسٹ** کے ذریعے، تاکہ پہلے کوئی ساتھی یا مینٹور اسے دیکھ لے۔ آپ یہ ہیکاتھون میں کریں گے۔

### یہ سبق کیسے کام کرتا ہے

بائیں طرف آپ کے پروجیکٹ کا فولڈر ہے: کسی فائل کو منتخب کر کے اس میں تبدیلی کریں (لکھتے ہی تبدیلیاں محفوظ ہو جاتی ہیں)۔ دائیں طرف **ٹرمینل** ہے: کمانڈ لکھیں اور **Enter** دبائیں۔ یہاں استعمال ہونے والی تمام کمانڈز دیکھنے کے لیے `help` لکھیں۔ جب لگے کہ کام مکمل ہو گیا ہے تو **میرا کام چیک کریں** دبائیں۔
