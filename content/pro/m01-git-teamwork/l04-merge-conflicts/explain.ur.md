---
title: مرج کنفلکٹس حل کرنا
summary: جب دو برانچز ایک ہی سطریں بدلتی ہیں تو git آپ سے فیصلہ مانگتا ہے۔ یہ عام بات ہے — طریقہ یہ ہے۔
---

زیادہ تر مرج آسانی سے ہو جاتے ہیں۔ لیکن اگر دو برانچز نے **ایک ہی فائل کی ایک ہی سطریں** مختلف طریقوں سے بدلی ہوں تو git کو نہیں پتا کہ آپ کون سی چاہتے ہیں۔ اسے **مرج کنفلکٹ** کہتے ہیں: git مرج روک دیتا ہے اور فائل میں اس جگہ نشان لگا دیتا ہے:

```text
<<<<<<< HEAD
<h1>Welcome to our club</h1>
=======
<h1>Hello, friends!</h1>
>>>>>>> title
```

- `<<<<<<< HEAD` اور `=======` کے درمیان آپ کی برانچ والا ورژن ہے۔
- `=======` اور `>>>>>>> title` کے درمیان اس برانچ کا ورژن ہے جسے آپ مرج کر رہے ہیں۔

اسے ٹھیک کرنے کے لیے:

1. فائل کھولیں اور فیصلہ کریں کہ اس میں کیا ہونا چاہیے: ایک ورژن، دوسرا، یا دونوں کا ملاپ۔
2. **نشان والی تینوں سطریں حذف کریں** (`<<<<<<<`، `=======`، `>>>>>>>`)۔
3. فائل کو `git add` کریں تاکہ پتا چلے کہ ٹھیک ہو گئی، پھر `git commit -m "Merge the new title"`۔

`git status` بتاتا ہے کہ کن فائلوں میں ابھی کنفلکٹ باقی ہے۔ ارادہ بدل گیا؟ `git merge --abort` سب کچھ مرج سے پہلے جیسا کر دیتا ہے۔

کنفلکٹس غلطیاں نہیں: ان کا مطلب ہے کہ دو لوگ ایک ہی حصے پر مصروف تھے۔ ٹیم میں بات کریں اور دونوں میں سے بہترین چنیں۔

### یہ سبق کیسے کام کرتا ہے

بائیں طرف آپ کے پروجیکٹ کا فولڈر ہے: کسی فائل کو منتخب کر کے اس میں تبدیلی کریں (لکھتے ہی تبدیلیاں محفوظ ہو جاتی ہیں)۔ دائیں طرف **ٹرمینل** ہے: کمانڈ لکھیں اور **Enter** دبائیں۔ یہاں استعمال ہونے والی تمام کمانڈز دیکھنے کے لیے `help` لکھیں۔ جب لگے کہ کام مکمل ہو گیا ہے تو **میرا کام چیک کریں** دبائیں۔
